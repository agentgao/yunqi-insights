00:02:07

真实云环境使用Agent的挑战

让 Agent 的产品在真实的云环境里面发生作用，其实是一个非常具有挑战的一个事情。有三个方面的问题是不可忽视的，这也是我们在 OpenAgent 这个产品里面去重点去做优化和改进的点。第一个是幻觉与误操作。这里面其实大家能理解，其实是一个非常危险的问题，因为现在 Agent 都是基于那个大模型嘛，大模型是一个概率型的模型。所以。多少会产生一些意想之外的操作。

00:08:03

那对于运营来说，最危险的就是叫做意外的去删除一些客户的资源，客户的数据。而往往又是这些操作又是一个不可逆的一个操作。随便举个例子，我们让 Agent 去清除我在测试环境里的这样的一个资源。但如果说 Agent 错误的理解了这个意图， 并且它又有权限去清理更大范围的资源的时候，它就可能会影响到我们的线上环境。那针对这样的问题，我们其实在 Harness 工程侧做了很多工作，包括对一些运行规则的一些强检测，包括对一些高危风险操作的识别和拦截，人工审核以及全链路的这样的一个审计。

00:08:41

此外，在 OpenAgent 里面我们引入了专门的形式化验证交叉机制，我们通过大模型和形式化交叉验证来确保 Agent 的行为是否和客户的意图保持一致。那形式化的这一块会在待会的这个分享里面， 会有我两位同事去做展开的这样一个分享。第二部分其实是关于成本，Agent 的运行需要烧 Token，然后 Agent 会创建各种各样的资源，买各种各样的服务，那也会可能会产生一些比如说资源泄漏的这样的一些问题。

00:09:13

那我们过去一个真实的例子，就是客户在部署一个应用的时候，然后 Agent 不断在里面犯错，但在每一轮犯错里面，它又会去创建出一些资源，但是又不删除，结果一个晚上它烧掉了上万元的这样的一个账单。那针对这样的问题，我觉得我们在 OpenAgent 里面做到几件事情。第一个是说精准的这样的一个询价机制和价格估算。第二个是我们能够去设定一个可靠的预算机制。

00:09:39

然后我们有这样的一个熔断保护和配额保护。第三部分是信息安全。Agent 其实现在已经逐渐成为业界最新的一个攻击入口。可以通过一些针对 AI 的攻击手段，可能可以通过 Agent 去获取到很多信息，会产生一些很严重的，包括像越权，信息泄露的问题。那我们在这个层面上来说，比如说通过传统的网络保护去作为我们安全边界，其实已经不太够了。我们在内部的实现过程中， 做了像短期凭证，最小权限，沙箱保护，然后签名代理，凭证代理， 然后像沙箱等等这样的一系列的机制，去保证我们的安全。
