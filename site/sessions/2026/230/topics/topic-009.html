构建全栈Agentic网络，让Agent连接世界

01:41:53

过去十几年，其实云计算网络做的工作，如果用一个词来形容的话，其实可以用“连接”这个词来概括。我们连接服务器，连接人，连接万物，但最终其实都是去连接人。但是进入AI时代之后，我们发现一个很有意思的变化，就是整个网络的连接正在发生结构性的变化。来自Cloudflare的一个报告显示，2025年非人类HTTP请求占比达到56.5%。

幻灯片 04

从 Cloud Network 升级为 Agent Native Network，让 Agent 连接世界

01:42:55 — 01:44:10 官网回放 ↗
祝顺民
01:42:56

面对这个问题，我们必须思考整个Agent对网络提出的需求和挑战。Agent所需要的连接主要体现在三个方面。第一个方面，Agent Ingress，智能体被世界连接，主要解决的问题和挑战是让Agent可以可信地被接入。第二个方面是Agent Runtime，智能体算力连接。主要面对的挑战是大规模的Agent如何快速地秒级的启停。这是整个Agent的基础。

01:43:38

第三个方面是Agent的Egress。智能体主动连接世界，核心面对的挑战是Agent如何安全、可控地连接世界。因此，我们将Cloud Network全新升级为Agent Native Network。我们希望让每一个智能体都像人一样，既安全又自由地使用网络。接下来我会分别展开介绍。

幻灯片 05

高弹高密 Agent 网络：为 Agent 提供极致的网络性能

01:44:10 — 01:46:52 官网回放 ↗
祝顺民
01:44:11

首先是Agent Runtime，智能体算力连接。左边这个图下面两层是传统云计算网络架构的层次图。最下面一层是L1物理网络，它主要由物理的交换机、物理的路由器组成，实现物理层面的连接。L2是在物理网络的基础之上去构建整个VPC的虚拟网络层，它核心解决的问题是将网络虚拟化。然后实现多租户，多租户的网络之间互相隔离。那么我们就在想，可不可以还是通过这一个L1，再加这个L2来面对Agent给网络提出的需求。

01:45:00

但是我们发现Agent的需求和原来的虚拟机非常不一样。因为Agent需要1秒钟拉起几十万个沙箱。第二，任务可能仅仅持续几秒钟。几秒钟的任务结束之后，大规模的沙箱就要全部的瞬间去释放。那这个需求背后的本质是什么？这个需求本质上是在对网络提出高弹性、高密度、大规模的需求。显然，原来的L1加L2已经无法满足这样的需求了。我们必须去重新构建一个Agent的虚拟网络层。

01:45:42

我们通过网络资源的弹性预热，将Agent沙箱的网络就绪时间缩短到100毫秒。以应对高弹性的这个挑战。我们通过网卡的多IP直通技术，让单服务器节点网卡密度达到5000多，来应对Agent提出的高密度的挑战。最后，我们通过轻量化的控制协议，实现每分钟在一个Region内百万规模的沙箱快速拉起来，以应对这个大规模的挑战。而最后这一点大规模的挑战，事实上是我们面对最大的挑战。

01:46:26

因为原本的数据面加控制面的实现里面，数据面去追求高性能，但从来没有说控制面要求性能也是极致的。恰恰Agent的沙箱提出了控制面的极致性能要求。整个Agent Runtime是整个Agent Native Network的基座。

幻灯片 06

应用型负载均衡 Application Load Balancer (ALB)：让 Agent 可信地被世界连接

01:46:52 — 01:48:28 官网回放 ↗
祝顺民
01:46:53

第二个方面是Agent的Ingress。一个Agent被创建起来之后，要能够被世界所连接，快速地连接，核心需要解决的问题是如何让Agent便捷地、安全可信地被访问。我们对我们的Application Load Balancer进行了升级。第一方面，我们支持多协议的接入，同时支持HTTP、WebSocket、SSE等多种协议接入。第二，我们支持身份认证，支持JWT、API Key等多种方式对请求进行身份认证。

01:47:33

最后，我们实现了动态的转发，当Agent被拉起的时候即可被路由，也就完成了在ALB负载均衡上面的注册。单个ALB的实例可以免注册挂载10万个后端的Agent的沙箱。但这里一个核心的变化是什么？以前我们用负载均衡的时候，一个虚拟机被挂在一个服务后面，是需要管理员显式地去做挂载这个动作。但是我前面提到，Agent需要在几秒钟之内拉起一个很大的规模，又在几秒钟之后要快速地释放掉，根本没有时间去完成这个注册的动作，所以免注册的可信访问是一个非常核心、关键的能力。

幻灯片 07

出口代理网关 Egress Proxy Gateway (EPG)：让 Agent 安全可控地连接世界

01:48:28 — 01:50:21 官网回放 ↗
祝顺民
01:48:29

从另外一方面，当Agent需要主动访问世界的时候，它面对的核心问题是如何为大规模的Agent提供在有约束基础之上，自由主动访问世界的能力。大家注意我用的词，刚才表述的顺序，这必须是在有约束基础之上，自由访问世界的能力。为了解决这个需求，我们全新研发了一个网关，叫Egress Proxy Gateway，专门应对Agent去访问互联网的时候，如何有效地进行路由管控并且保证安全。它提供3个能力。

01:49:14

第一个是智能选路的能力，可以基于域名、URL、HTTP Header、源IP，作为关键词的策略，精准地去选择出口的路径和出口的IP。第二方面，它支持管控和审计，Agent敏感的访问和操作，可以被拦截和追溯。并支持一键开启云防火墙的深度联动，更深入地进行内容的控制。前段时间有一个新闻，就是Agent把一些代码资产进行了泄露。那我们在用Agent的时候，这一点安全就非常关键。

01:49:57

还有一点就是大规模的并发，那我们专门为此基于整个我们的弹性NFV的架构，去架设我们的这个EPG Egress Proxy Gateway来支持千万级别的并发连接。总的来说，EPG就是让Agent在安全可控的边界内自主地连接世界。

幻灯片 08

NIS 网络 AI 助手：Agent 时代的网络，由 Agent 来运维

01:50:21 — 01:51:39 官网回放 ↗
祝顺民
01:50:21

前面介绍了Agent连接世界的网络，我们如何来构建这个Agent Native Network。但是我们反过来想一下。这张为Agent打造的网络本身的运维，是不是也应该让Agent自己来运维？我觉得这个答案是肯定的。在AI时代里面，网络运维的主体应该像网络流量的主体一样，从人变成Agent，那么也就意味着网络运维的主体也应该是从工程师变成智能体。

01:50:56

所以我们推出了洛神网络的AI助手，它积累了33个专家的经验，覆盖网络运营的选型、配置与变更。在感知层面，AI助手还可以主动的去支持被动告警的处理，也支持主动定时发起巡检。在判断层，通过网络仿真引擎ZooSim去验证问题的根因。在自治层，也是最关键的一层，是由Agent根据设定的SOP和Skill进行自我的问题修复。Agent时代的网络也应该由Agent自己来运维。
