幻灯片 05

新一代 CPFS：全栈自研，为百万卡模型训练加速

00:37:59 — 00:41:45 官网回放 ↗
蒋江伟
00:38:02

针对训练场景，我们今天正式发布全新一代的CPFS，其单文件系统的容量规模从20个PB扩大到了100个PB。截至目前，所有云计算公司里面，我们肯定是最大的，这也是我们结合客户的痛点来专门研发的。大家都知道，在自动驾驶的一个场景，它的训练数据，我们先不说其他中间状态的数据，单单训练的数据已经远远超过了20PB。所以天然它就需要一个更大的文件系统。

00:38:41

这样，就是所有的算力卡，就是整个算力的集群能够共同访问，就共享去访问同一个文件。当然，在具体的训练过程中，它的数据量并没有那么大。但是我们跟一些训练的工程师交流的过程中可以看到，他列了一些文件的列表，就是说每个文件它有个目录，都基本上是处在一个什么状态呢？都处在一个满盘的一个状态。这时候怎么办呢？我的同事，我们自己内部做训练的同事，还有他的运维找过来说：“你们能不能分析一下哪些数据没有使用、长时间没有使用，能不能删除？

00:39:26

”这时候就涉及到一个问题：你是删除呢，还是说重新开一个文件系统？所以这是一件非常伤脑筋的事情。因为没有一个团队说，我的数据是可以被删除的，因为他不确定这个数据能不能被删除。而全新一代的CPFS，单个文件系统就已经达到了100PB，相应的文件数量也从百亿支持到了万亿。在性能上面，我们结合这些场景也是提出了2点的要求。第一个，随着模型迭代速度的加快，Checkpoint的频率从几十分钟缩短到分钟级。

00:40:05

所以对文件系统的IO能力提出了更高的要求。第二个，模型的参数从千亿迈向10万亿，单次写入的数据量也是大幅度增加。所以CPFS单文件系统的吞吐能力可以达到100TB，100TB每秒和亿级的IOPS的能力。整体的性能指标呢，可以这么评价，就是说，整体的性能指标平均值应该提升2倍以上，跟之前的版本相比，提升2倍以上。其中对于频繁访问的一些元数据的场景，应该是提升了10倍以上的一个性能。

00:40:49

在实测的一些场景，比如说在Qwen的训练实测场景，我们观察到整个效果也是非常好。比如说像Checkpoint，它的写入可以做到从150秒降低到了15秒。在成本上面，容量的规模也变得更大，也需要有更好的TCO。虽然和计算相比，存储的成本占比还是非常低的，因为计算的成本大家都知道它非常的昂贵。我们在产品架构上，也是做了优化。CPFS提供了多个档位的存储规格的能力，以及智能的生命周期的管理能力。

00:41:28

如果我们举个例子，比如说把20%的数据放到一个高规格，就是性能更高的存储里面，80%存入一个相对低频的存储规格里面，那么整体的成本可以下降69%。

在推理的场景，其实大家都一样，都在努力提升一个目标，包括公司内和公司外的一些模型的客户，就是提升KV Cache的命中率。而现在呢，长上下文、多轮对话正在成为趋势，导致KV Cache数据爆发式的增长。如果要保持命中率，那么需要有更大的缓存的空间。今天我也是代表阿里云正式发布全球首款KV Cache Store产品。KV Cache Store的大容量可以帮助推理大幅度的提升命中率，但是在成本上面，我看有好多场合都讲到了，成本只需要DRAM的几十分之一，应该是在1/30～1/50。

00:42:34

我们有客户，就是前段时间，应该在一两周，Kimi的模型推理，在接入了KV Cache Store之后，它的缓存窗口扩大了9倍，TTFT下降了54%，我们的吞吐也是提升了20%。这个数据呢，就是他在什么都不做的情况下，只接入了KV Cache Store就实现了这样的效果，成本也大幅度下降，命中率大幅度提升。我们也发现在内部，我们自己的Qwen模型，就是百炼的推理平台，阿里云对外服务是百炼平台。

00:43:15

那么百炼推理平台，在前面几周，在以非常快的速度接入KV Cache Store，我们的同事都在加班，可能今天都在加班，帮他们系统上线，把整个KV Cache Store在各个Region部署，并且上线。原因非常简单，就是上去了之后，他们给我们的反馈是，Prefill的卡直接节省一半，这是非常多的钱。从性能上面，我们KV Cache Store整体的定位，如中间这个图，是在G3.5层。

00:43:53

我们通过算力亲和性的部署，也就是在整个算力集群的边上，在就近、在网络最优的条件下面部署整个存储的集群，提供了数十TB每秒的吞吐能力和亿级的IOPS能力。时延当然不是非常重要，因为大家都知道推理过程它的时延并不那么重要，但是我们的时延也是做到了亚毫秒级别。当然，最重要的是使用非常简单，因为它提供了简单的KV接口。大部分的推理框架，我们都做了适配，所以如果是开源的，你只需要通过配置就可以接入。
